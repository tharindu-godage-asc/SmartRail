# Customer-Service Representative — Stakeholder Transcript

- Pain point: Cannot tell whether a delay is verified or merely reported when answering passenger enquiries.
- Source of truth: [SmartRail discovery](../context/smartrail-discovery.md)
- Role perspective: [Customer-Service Representative persona](../personas/customer-service-representative.md)

## Response

*   **Discovery addresses the pain point:** D-10 and D-20 explicitly separate "timing" (immediate) from "reason" (post-verification), ensuring unverified data is not presented as fact.
*   **Verification status is visible:** D-20 mandates a shield badge to distinguish verified from unverified information, directly supporting the need to know if a delay is confirmed.
*   **Role alignment:** D-11 confirms customer information is merged into the controller role for the MVP, meaning the controller holds the authoritative status needed to answer enquiries.
*   **Open uncertainty:** The discovery does not specify the exact interface or workflow for the controller to retrieve this status during a live passenger enquiry.
*   **Constraint:** D-46 restricts badges to verification time, but does not define how a representative communicates "awaiting verification" versus "stale" data verbally or via text.
